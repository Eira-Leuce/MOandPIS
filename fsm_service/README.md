# fsm-service: исполнение процессов по конфигурации

МОиПИС, задание 3-1-1 «Приемы моделирования бизнес-логики», **вариант 3** — «Управление заказом на поставку стандартной продукции».

Система описывает классы объектов, готовые объекты, пользователей и шаблоны процессов в конфигурации (YAML) и исполняет процессы общим механизмом. Названия классов, состояний, действий и правила варианта в обработчик не зашиты. Реализованы **оба механизма объектной модели**:
- наследование параметров классов;
- составность объектов: ссылки на другие объекты и проверка их параметров агрегатором.

## Запуск

```bash
pip install -e ".[test]"
```

Тесты:

```bash
python -m pytest -q
```

Демонстрация варианта 3 по готовому сценарию (журнал пишется в `log.jsonl`):

```bash
python -m fsm_service examples/variant3 --script examples/variant3/demo.txt
```

Между командами сценария по умолчанию пауза 1,2 с. Параметр `--delay 2` задаёт другую паузу, `--delay 0` убирает её. С параметром `--step` следующая команда выполняется по нажатию Enter — так удобнее всего показывать вживую:

```bash
python -m fsm_service examples/variant3 --script examples/variant3/demo.txt --step
```

Вывод цветной, если программа запущена в терминале. `--color never` отключает цвет, `--color always` включает его принудительно.

Интерактивный режим: команды вводятся с клавиатуры.

```bash
python -m fsm_service examples/variant3
```

Пример из раздела 1 задания (конфигурация без изменений):

```bash
python -m fsm_service examples/document_approval --script examples/document_approval/demo.txt
```

### Команды консоли

| Команда | Что делает |
|---|---|
| `start <пользователь> <объект>` | запустить процесс над готовым объектом |
| `act <пользователь> <объект> <действие>` | выполнить действие |
| `{"type": "action", "user": ..., "object": ..., "action": ...}` | та же команда в формате JSON |
| `status <объект>` | параметры объекта, состояние процесса, кому какие действия доступны |
| `objects`, `users` | таблицы объектов и пользователей |
| `log`, `log json` | журнал текущего запуска: таблицей или в исходном JSON |
| `help`, `quit` | справка, выход |

В файле сценария строка `## текст` печатается как заголовок раздела, `# текст` — как пояснение.

Результат каждой команды печатается и записывается в журнал JSONL: одна запись — одна строка.

```json
{"time": "2026-11-03T16:05:21", "command": {"type": "action", "user": "popova", "object": "ord-1", "action": "approve"},
 "user": "popova", "object": "ord-1", "state_before": "price", "state_after": "price",
 "result": "rejected", "reason": "требуется роль economist (у пользователя 'popova' её нет)"}
```

`result` принимает значения `accepted` (выполнено), `rejected` (отказ) или `error` (некорректная команда, неоднозначный переход, сбой). Отказ и ошибка не меняют состояние процесса. Рабочие данные хранятся только в памяти: после перезапуска объекты загружаются заново, запущенных процессов нет.

## Конфигурация

Каталог конфигурации (например, `examples/variant3/`) содержит:

| Файл | Что описывает |
|---|---|
| `classes.yaml` | классы и параметры: `integer`, `decimal`, `string` с `min`, `max`, `default`; составы (тип — класс) с `quantity_min`, `quantity_max`; `parent` для наследования |
| `objects.yaml` | готовые объекты. Пропущенное скалярное поле получает `default`, явный `null` остаётся незаданным, пропущенный состав — пустой список |
| `users.yaml` | роли и пользователи |
| `<шаблон>.yaml` | шаблон процесса: `class` (точный класс объекта), `create_roles`, `actions`, `predicates`, `states`, `transitions` |

Правила:
- у класса не более одного шаблона, и поле `class` шаблона точно совпадает с классом объекта. **Шаблоны не наследуются**;
- границы параметров не мешают загрузке объекта: их проверяют предикаты переходов.

## Предикаты и условия

- **Предикат параметра** — `parameter`, `operator` и, для сравнения, `value`:
  - `filled`: пустая строка считается заданной, пустой состав — нет;
  - `=`, `!=`;
  - `<`, `<=`, `>`, `>=` — для чисел и составов;
  - `in_range` — `min`–`max` у числа, `quantity_min`–`quantity_max` у состава.

  У состава во всех сравнениях используется количество. Незаданное значение, в том числе параметр, которого нет у класса, делает предикат ложным, включая `filled`.
- **Путь `состав.параметр`** с обязательным `aggregate`: `all` (для пустого состава истинно) или `any` (для пустого — ложно). `in_range` берёт диапазон класса входящего объекта.
- **Предикат класса** — `class: <id>`: объект принадлежит классу или его подклассу.
- **Условие** — в ДНФ. Строки `condition` — группы «И», между группами «ИЛИ», `not` отрицает один предикат. Переход без условия разрешён всегда.

Условие компилируется в дерево выражений (паттерн Интерпретатор): `[[a, b], [not c]]` → `Or(And(a, b), And(Not(c)))`.

Агрегатор выбирается по имени из реестра «имя → функция» (паттерн Стратегия, `conditions.AGGREGATORS`). Новый агрегатор добавляется одной регистрацией, без изменения вычисления предикатов:

```python
from fsm_service import register_aggregator
register_aggregator("none", lambda results: not any(results))
```

Неизвестное имя агрегатора даёт понятную ошибку при загрузке шаблона.

## Обработка команды

```
сообщение → parse_command → Start / Action (Команда)
         → ProcessEngine.start / act
             start: пользователь и объект есть, шаблон точного класса есть,
                    роль из create_roles есть, процесс ещё не запущен → начальное состояние
             act:   пользователь и объект есть, процесс запущен
                    → ProcessInstance: не конечное состояние → роль состояния →
                      переходы по (состояние, действие) → условия:
                      ни одного → отказ, ровно один → переход, несколько → ошибка неоднозначности
         → запись в журнал (одна точка — ProcessService)
```

## Устройство

| Модуль | Назначение |
|---|---|
| `classes.py` | классы объектов и параметры, наследование над данными (Объект-тип) |
| `objects.py` | готовые объекты, значения по умолчанию, составы, контекст вычисления предикатов |
| `conditions.py` | предикаты, пути, агрегаторы (Стратегия), дерево условий (Интерпретатор) |
| `service.py` | `ProcessTemplate` — общие правила; `ProcessInstance` — экземпляр процесса: табличный автомат с очередью сообщений и динамической регистрацией хэндлеров, состояний и переходов |
| `engine.py` | `ProcessEngine` — запуск процесса над объектом и выполнение действий |
| `commands.py` | команды `Start` и `Action` (Команда), `ProcessService`, журналы `JsonLinesLog`, `MemoryLog` (внедрение зависимости) |
| `config.py` | загрузка шаблонов и каталога конфигурации |
| `users.py` | роли и пользователи |
| `cli.py` | консольная программа |

Шаблон общий для всех экземпляров. Текущее состояние хранится в экземпляре (`ProcessInstance`), а не в шаблоне, поэтому независимые экземпляры можно запускать одновременно. Это задел для задания 3-1-2.
